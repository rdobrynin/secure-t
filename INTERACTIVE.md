
== Интерактив: «Терпеливый Артем» ==

> **Для дизайнера:** пошаговый интерактив — 4 шага с переходами. На каждом шаге: симуляция терминала + пояснение «что происходит технически» в боковой панели. Читатель управляет темпом: кнопка «Следующий шаг» после каждого блока. На финальном экране — три ошибки банка и вопрос «Что изменило бы исход?» с вариантами ответа. Персонаж Артема — схематичная иллюстрация, минималистичный стиль. Терминальные блоки — тёмный/светлый фон, моноширинный шрифт.

**Дано:** Артем — аналитик данных в небольшой компании. Днём он строит графики в Excel и пьёт третий кофе, а по ночам — перехватывает корпоративный трафик крупного банка и аккуратно складывает его на жёсткий диск. Артем не спешит. У него есть план.

**Цель:** показать атаку HNDL изнутри — от первого перехвата до расшифровки архивов шестилетней давности.

**Шаг 1. Сбор урожая**

_2025 год. Арендованный сервер где-то в Европе._

Банк использует TLS 1.3 с RSA-2048 и ECDH на кривой P-256. Всё по учебнику. Всё надёжно.

«Сейчас — да», — думает Артем и нажимает Enter.

```
[CAPTURE] TLS session dump → archive_2025_01.enc  [4.2 GB]
[CAPTURE] TLS session dump → archive_2025_02.enc  [3.8 GB]
[CAPTURE] TLS session dump → archive_2025_03.enc  [5.1 GB]
...
```

Трафик зашифрован. Артема это не беспокоит.

_Технически:_ злоумышленник записывает зашифрованные TLS-сессии целиком — включая обмен ключами (ClientHello, ServerHello). Расшифровать сейчас невозможно. Но зашифрованные данные никуда не деваются.

**Шаг 2. Холодное хранение**

```
[UPLOAD] archive_2025_*.enc → cold_storage/bank_harvest/
[STATUS] Total stored: 61.4 GB
[COST]   Monthly: $1.23
[NOTE]   "Дешевле, чем подписка на стриминговый сервис."
```

Артем закрывает ноутбук и идёт спать. Завтра — обычный рабочий день.

_Технически:_ стоимость холодного хранения в 2025 году настолько мала, что накапливать зашифрованный трафик годами — экономически тривиально.

**Шаг 3. Ожидание**

_2025 → 2026 → ... → 2031_

Однажды Артем видит заголовок:

> **«Google объявляет о первом CRQC: RSA-2048 взломан за 4 часа»**

Артем открывает терминал.

_Технически:_ CRQC способен запустить алгоритм Шора на реальных ключах. Для RSA-2048 это ~4000 логических кубитов, для ECDH P-256 — ~2330. Эллиптические кривые падут первыми.

**Шаг 4. Час расплаты**

_2031 год. Артем достаёт архивы шестилетней давности._

```
[LOAD]    cold_storage/bank_harvest/ → local_decrypt/
[TOOL]    quantum_shor_client --algorithm ECDH-P256
[TARGET]  archive_2025_01.enc

[PROGRESS] Recovering session key...  ██████████  100%
[SUCCESS]  Session key recovered: a3f9...b21c
[DECRYPT]  archive_2025_01.enc → archive_2025_01_plain.json

[PREVIEW]
{
  "transaction_id": "TXN-20250115-009823",
  "amount":          2850000,
  "currency":        "RUB",
  "auth_token":     "eyJhbGci..."
}
```

Шесть лет ожидания. Один скрипт. Полный архив транзакций.

«Терпение», — говорит он сам себе и открывает следующий файл.

_Технически:_ алгоритм Шора восстанавливает приватный ключ из публичного за полиномиальное время. Имея ключ ECDH-сессии, атакующий расшифровывает всю переписку — включая данные, переданные годы назад.

**Что изменило бы исход?**

Банк совершил три ошибки: использовал ECDH P-256 (уязвим для алгоритма Шора), не внедрил гибридный обмен ключами и откладывал миграцию. Если бы банк добавил ML-KEM (Kyber) рядом с ECDH до начала сбора архивов — Артему понадобились бы одновременно квантовый компьютер и неизвестная уязвимость в Kyber. Артем закрыл бы ноутбук и пошёл спать уже без планов на утро.
